# 任务分解：控制每个执行块的粒度

> 🚧 本节正在开发中。

任务分解的核心目标是让每个执行块在 context window 崩塌之前完成。分解有两个维度。空间维度按模块边界和 API 契约切分，让每块的作用域清晰可控。时间维度通过频繁的 session 重置，防止单个会话中 token 累积过多。

粒度的选择是关键权衡。任务块太大，执行到后半段时上下文已经退化，产出质量不可靠。任务块太小，块与块之间的协调开销（交接、对齐、重复建立上下文）反而成为主要成本。最优粒度取决于具体项目的模块耦合度和上下文复杂度，没有通用公式，但有判断框架。这个框架建立在第二章信息分层的基础上：每个任务块需要的上下文量决定了它的合理大小。
