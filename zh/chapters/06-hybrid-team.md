# 组织重构：当 Agent 改变了协作的前提

> 🚧 本章正在开发中。以下是核心论点的概要，完整内容将在后续版本发布。

卷二解决的是个人效率问题。一个人指挥多个 Agent 并行，个人产出可以达到几十倍。但当团队里有几个人都开始这样做的时候，一个新的瓶颈出现了：团队的分工和流程是为人类执行速度设计的，它扛不住 Agent 的产出速度。

最直观的症状是 review 排队。Agent 一天产出 20 个 PR，但 code review 流程是按照人一天写一到两个 PR 的节奏设计的。部署窗口一天两次，PR 堆积，合并冲突频发。代码可以秒出，但组织流程把它堵在了管道里。

比流程更深层的问题是团队结构。传统团队按功能分工：前端两人，后端三人，QA 一人。这种分法假设每个人的产出大致相当，工作量可以按人头均分。当 Agent 让个人产出差异从两倍拉大到十倍，这个假设就不成立了。会用 Agent 的人觉得自己干了大部分活却拿一样的薪水，不会用的人觉得焦虑和被边缘化。问题不是谁更努力，而是组织结构的设计前提变了。

Conway 定律在 Agent 时代仍然适用：系统的架构反映组织的沟通结构。如果团队边界没有重新划定就大规模部署 Agent，产出的代码会反映旧的组织边界，集成的摩擦不会减少只会加速暴露。正确的顺序是先定义清晰的模块边界和接口契约，再让 Agent 在边界内高速产出。

本章从结构失效的根因分析开始，经过瓶颈转移的诊断，到流程再造的具体原则。核心论点是：Agent 时代的组织瓶颈从代码产出转移到了组织设计，解决它需要重新定义分工、重新设计流程，而不是简单地让更多人用上 Agent。
