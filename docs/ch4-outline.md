## 章级 takeaway

orchestrator 从人转移到 harness 之后，spec 从共享工作台变成意图载体。这份载体服从一条原则。Agent 消费的每个单元，在注意力承载力内自足承载本单元任务所需的全部意图。产出这样一份载体超出单个人的能力。产出方法是人和大模型共同生产。二者的合作接口由一条元原则定义。大模型只向人抛回可判定的决策。

## 章的论证链

原则立起来之后，读者会发现满足它的载体大到一个人做不出来。这条约束推出新方法。方法本身需要一条元原则来定义人和大模型的接口。最后一节把原则和方法合起来在一个真实项目上跑一遍，验证论证成立。

四节的角色：

- 4.1 建立议题。spec 从工作台变成载体
- 4.2 提出原则。载体的一条原则
- 4.3 引入方法。共同产出与可判定接口
- 4.4 走完一遍流程。从粗略意图到可用载体

## 4.1 spec 从工作台变成载体

### Section takeaway

卷二相对卷一的物理变化只有一条。执行时人不在每个子空间的现场。这一条推出 spec 角色的转变。工作台承载对话状态。载体承载完整意图。

### 段落

**段 1：卷二的物理事实**

Takeaway：多 Agent 并行、长任务跨多个 context，本质是同一物理事实的两种形态。执行时人不在。

从卷一到卷二唯一的物理变化就是这一条。其他所有变化都是它的推论。这个开场明确锚定这一条，后面的章节都从它出发。

**段 2：物理事实推出 spec 角色的变化**

Takeaway：卷一里 spec 是工作台。卷二里 spec 是载体。

卷一场景下人在现场随时和 spec 对话。spec 承载当下这一步的信息就够。凡是没写清楚的地方，人下一句就能补。

卷二场景下人退出现场。spec 独自承担传输意图的任务。凡是人在场会即时补充的东西，都要预先编码进载体里面。

工作台承载对话状态。载体承载完整意图。两者是完全不同的东西。

**段 3：章的展开**

Takeaway：这一章走三步。提出原则，引入方法，跑一遍流程。

- 4.2 提出载体应满足的原则
- 4.3 引入产出方法，含一条元原则
- 4.4 用一个真实项目走完全流程

### 与卷一的引用点

卷一 02b 的分层原则、三维度框架、02c 的迭代对齐这些结论在这里都继续成立。开场只承接结论，不重述框架细节。

### 写作陷阱

- orchestrator 是一套机制。避免把它讲成一个软件组件
- 4.1 只做开场铺垫。避免在这里泄露 4.2、4.3、4.4 的展开细节
- 段 2 的对比要克制。用陈述句表达差异，避免根本、巨大这类修饰词

## 4.2 载体的一条原则

### Section takeaway

载体服从一条原则。Agent 消费的每个单元，在注意力承载力内自足承载本单元任务所需的全部意图。这条原则里的两个变量互相耦合。单元大小和自足性不能分开优化。所有操作层做法（分块、按决策边界切、每块自足）都是这条原则的推论。

### 段落

**段 1：从物理事实推原则**

Takeaway：Agent 在子空间里只能读它拿到的东西，处理能力有上限。两条物理事实联合定义原则。

Agent 只能读它拿到的东西。所以载体必须把 Agent 完成任务所需的意图全部装进 Agent 会读的地方。

Agent 处理能力有上限。所以 Agent 一次读的量不能超出承载力。

联合起来就是一条原则。Agent 消费的每个单元，在注意力承载力内自足承载完成本单元任务所需的全部意图。

**段 2：两个变量为什么不能分开**

Takeaway：单元大小和自足性是同一条原则的两个变量。脱离对方讨论就失去定义。

自足性是相对性质。自足必须相对于某个边界才有意义。边界由单元大小给定。

单元大小也是相对性质。不知道要装什么，就不知道多大算合适。装的东西由自足性决定。

两个变量互为对方的约束，只能联合优化。这就是为什么原则只有一条。

**段 3：原则落到操作层的推论**

Takeaway：原则满足之后载体必然是分块的，每块自足，切在决策边界。

分块从注意力承载力推出。载体一次读不完就要分块。

每块自足从原则直接推出。每块的边界由单元大小定，边界内的意图由自足性装齐。

切在决策边界是操作性发现。决策边界是意图能被自然自足包装的地方。按代码模块切的话，跨模块的决策会漂在切分线上，破坏自足性。

这三个推论不是三条平行的原则。它们是同一条原则在操作层的展开。

**段 4：这份载体的规模远超卷一**

Takeaway：满足这条原则的载体必然比卷一的 spec 大得多、结构化得多。

预先编码的东西包括决策的推理过程、边界条件、边缘情况的处理策略。凡是卷一里人在现场即时补充的，都要写下来。

一份 spec 的规模量级因此上升。产出这样一份 spec 的能力从哪里来，是 4.3 要回答的问题。

### 侧栏候选

拥抱冗余（放段 3 旁边）。自足单元之间会有信息重叠。这服务的是分发对齐目标。DRY 优化的是文档维护成本目标，两者优化对象不同。

### 素材归属

- 从物理事实推原则：段 1（胥克谦"你把文档拆成二十个也得都读完"、"开头结尾认真读，中间跳读"）
- 决策边界的操作性论证：段 3
- 载体比卷一大：段 4（胥克谦"事实上包含的要多得多"、"要在文档里给大模型开会"）

### 与卷一的引用点

卷一 02b 的分层原则在这里继续成立。这里只是在每层内部叠加一条新原则。

### 写作陷阱

- 原则只有一条。避免在段 2 之外任何地方把单元大小和自足性当作两条并列
- 段 3 的三个推论要放在同一段展开。分成三段会让读者又觉得是三条原则
- 段 4 只做承接，不展开产出方法

## 4.3 共同产出与可判定接口

### Section takeaway

产出这份载体的方法是人与大模型共同生产。二者的合作接口由一条元原则定义。大模型只向人抛回人能判定的决策。判定能力由领域知识和决策杠杆共同决定。抛回时的呈现形式必须匹配抛回对象的领域表达。

### 段落

**段 1：单人无法产出**

Takeaway：满足 4.2 原则的载体在体量和一致性两个维度上都超出单人能力。

体量维度上，需要预先编码的决策点数量级远超卷一。

一致性维度上，预先编码的决策之间彼此耦合。改动一处会牵动多处。单个人无法维持整体的一致性。

原因是人的工作记忆和一致性维护能力有物理上限，与意愿、经验、能力水平无关。

**段 2：共同生产是唯一方法**

Takeaway：产出这份载体只能通过人与大模型共同生产。

大模型承担细节生成、覆盖检查、扩展推理。这些是它能做好的部分。

人承担意图判断。大模型无法凭空知道用户到底想要什么。

双方之间需要接口。接口的设计决定合作能否跑通。

**段 3：接口由元原则定义**

Takeaway：接口由一条元原则定义。大模型只向人抛回人能判定的决策。

抛回不能判定的决策等于形式主义。人无法真正做出选择，大模型也无法真正拿到反馈。整个循环空转。

判定能力由两条同时决定。第一，人在此领域内具备识别能力。第二，此决策的杠杆值得人投入注意力。两条同时成立才构成有效的抛回。

同一个人在不同领域中的判定能力差别巨大。熟悉的领域里可能六七成的决策点能识别。陌生领域里可能九成以上是盲区。判定能力与领域绑定，与职位无关。

**段 4：呈现形式也是元原则的一部分**

Takeaway：大模型抛回决策的呈现形式必须匹配抛回对象的领域表达。

给产品经理抛回的决策要用产品行为的语言。给工程师抛回的决策要用技术权衡的语言。

呈现形式错误时，客观上可判定的决策也会变得实际上不可判定。面前是一份满是陌生技术术语的架构方案，理论上具备判定能力也无从下手。

这一条推出大模型在共同生产过程中需要做的额外工作。除了给出决策，还要以对方领域可接受的形式呈现。

### 侧栏候选

PRD 占产品价值百分之八十到九十（放段 3 旁边）。前期决策的杠杆之高，值得投入大量时间，是杠杆判断的一个极端例子。

### 素材归属

- 单人无法产出：段 1（胥克谦"百分之九十九的人没有能力搞定意图"、"和大模型开会"的核心动机）
- 共同生产循环：段 2（胥克谦"大模型提方案，我提修正，大模型改"的多轮对话流程）
- 人可判定：段 3（胥克谦"面对电脑的这个人的可决策性"、教育项目与开发工具的领域对比）
- 呈现形式：段 4。抽象成匹配对方领域表达。用户体验只是这一原则的一个应用领域

### 与卷一的引用点

卷一里人做意图对齐是判断题。这里升级为人做哪些意图对齐，加了能不能做作为第二条判定条件。

### 写作陷阱

- 段 3 的两个判定条件用一句话说完，不需要单独展开成两段
- 段 4 讲呈现形式。原则是匹配对方领域表达。用户体验只是一个例子，写作时不要陷进用户体验主线
- 段 1 讲单人无法产出时不要变成对读者能力的评价。这是所有人的物理上限，与具体读者水平无关

## 4.4 从粗略意图到可用载体

### Section takeaway

在 4.3 的方法和元原则下，一份满足 4.2 原则的载体如何一步步长出来。用一个真实项目走完全程。终点验证载体的每一块确实满足原则。

### 段落

**段 1：起点**

Takeaway：起点是一个粗略的顶层意图。

意图当前只有一句话或一段描述。距离满足 4.2 原则差得很远。缺决策点、缺边界条件、缺完整性。

用一个真实项目描述这个起点，让读者对起点和终点的距离有具体感受。

**段 2：迭代循环**

Takeaway：原则满足是通过多轮循环逐步逼近的。

一轮循环包含四步。大模型扩展意图。大模型抛回人可判定的决策。人做判定。大模型依据判定精修。

每一轮循环都严格遵守 4.3 的元原则。大模型抛回的决策必须是人可判定的。判定不了的决策由大模型自己做，或者转成可判定的形式再抛。

载体里预编码的决策数量每一轮上升。边界条件每一轮更清晰。整体一致性通过大模型的覆盖检查维持。

**段 3：迭代过程中载体形态的演化**

Takeaway：单元大小和自足性随着意图逐步外化，逐步收敛出来。

早期几轮载体是一个大块。自足性谈不上。单元大小也没到硬约束。

中期载体长到注意力承载力附近。读者会感觉到读不完的信号。这是分块的触发时机。

分块时决策边界是自然的切分线。切完之后每块内部的自足性才成为可评估的目标。

后期几轮循环的重点转向每块自足性的验证。

这一段展示单元大小和自足性联合演化的过程，回扣 4.2 段 2 的耦合性。

**段 4：验证终态**

Takeaway：终态载体的验收标准是 4.2 原则满足。

拿任意一块喂给 Agent。Agent 能独立完成本块任务，就是自足性和单元大小联合成立的操作性检验。

Agent 完不成的时候，回看是缺依据还是过载。缺依据是自足性漏了。过载是单元大小超了。

这个验收标准也是 4.4 案例支撑的论断。4.2 原则加上 4.3 方法确实能产出一份可用的载体。
