# 卷二 Outline

> 本文是 5 月版底稿（主仓库未 track 的 `docs/volume2-outline.md`）的更新版。核心 framing 有一次校准：卷一到卷二不是"同一套 principle 在规模下重新实现"，而是**每一章的对象都从操作层升到机制层**。
>
> 更新时间：2026-07-09。

---

## 一、卷二的定位

### 全书主轴

- 卷一：1 → 10x 单兵作战的工程化跃迁
- 卷二：10x → 100x 规模化 Agent 开发
- 卷三：100x → 组织级跨团队工程治理

### 卷二的核心 framing

**卷一里人是 orchestrator——你决定切什么、看什么、改什么。卷二里人做不了 orchestrator，这一层要由 harness 来承担。**

三章分别回答 harness 作为 orchestrator，在规约、验证、演进上要具体做什么。

多 Agent、长任务是**触发原因**（人为什么退出 orchestrator 角色），不是主题。主题是 harness 接管 orchestrator 之后要承担什么。这也决定了卷二的章名回到规约 / 验证 / 演进，和卷一对位，而不叫"自主执行"或"多 Agent"。

### Motivation

**人的注意力有限，在规模化下被几何倍数放大，这是不可解决的。**

- 不是要被解决的"麻烦"，是必须接受的强制约束
- 决策点、状态、异常、变更、历史在规模下都是几何级放大，人脑不会因为项目变大就升级
- 卷二所有 principle 和 solution 都是从这一条根上长出来的应对

### 从 motivation 推出的判断：harness 必然演化

- harness 不可能一次造对（人注意力有限，看不到还没暴露的失效模式）
- 不完备的 harness 会让信息漏掉、让验证在新场景下失效
- 失效后人要去几十万行代码里捞问题——再次触发注意力危机
- 所以必须有演化机制让 harness 持续完备

根因是 bounded attention，**不是**"环境在变"。Linux 也面对持续变化的环境，但内核架构非常稳定，环境变化本身不是普适规律。

## 二、卷一 ↔ 卷二的对位

| | 卷一（人是 orchestrator） | 卷二（harness 是 orchestrator） |
|---|---|---|
| **规约** | 帮你把意图说清楚 | 让意图结构本身可被机制分发 |
| **验证** | 帮你检查产出，你兜底 | 机制独立兜底，人不在场 |
| **演进** | 你改 harness | harness 自己发现要改哪里 |

每章开场都从"**卷一里这件事你在做、卷二里你做不了了、harness 要接管**"起手，让读者的心理跃迁明确。这不是"考虑更多"，是**每一章的对象**都变了。

## 三、三章的 takeaways 与子节大纲

### 第四章 规约：让意图能被并行分发

**要回答的问题**：当 harness 要接管切分和分发时，意图的结构本身要怎么变？

#### 核心 Takeaway

1. 卷一"一份 spec 给一个 Agent"在多线程下不够——不是 spec 写错了，是要被切成多份分发时切分本身会丢意图
2. **决策边界与人可判定性**——顶层决策必须留人，子空间决策 offload 给 AI。但抛给人的决策必须是**人有能力判断的**信息。杠杆判断（值得人参与）和可判定性判断（人能判断），两个一起才能定义有效的人机分工
3. 每个子空间的规约必须**自包含**。多线程下 Agent 没办法回头查上层，DRY 服务的是人的维护成本，自包含服务的是分发对齐，两者优化目标不同
4. 拆得足够小是为了 **attention 负载受控**。按决策边界 / 模块 / 单元 / 服务拆，不按代码模块

#### 子节

- 4.1 卷一画面在多线程下的失效（开场）
- 4.2 决策边界与人可判定性
- 4.3 自包含与反 DRY
- 4.4 拆分粒度：attention 是硬约束（原子任务 + 状态机作为运行时落地）
- 4.5 案例：一份意图走完顶层 → 子空间

#### 素材归属

- 决策边界、"人可决策性" → 4.2
- 上层决策依据必须体现在下层文档、自包含反 DRY → 4.3
- 拆到 attention 受控、按模块 / 单元 / 服务拆 → 4.4
- 原子任务 + todo 状态机 + 持久化 → 4.4 作为落地例子或侧栏，不独立成节

### 第五章 验证：当人不再能兜底

**要回答的问题**：当 harness 独立兜底时，验证机制要长成什么样？

#### 核心 Takeaway

1. 卷一验证以人为最终裁判、自动化为辅助。多线程下带宽和盲区任一破坏，前提失效
2. **Defense in depth：硬门禁 + 软门禁分工**。每层都拼命做，但承认单层必有盲区，多层叠加靠的是"每层抓不同类型的漏"。硬门禁确定性、只查格式；软门禁能查语义、会漂
3. **文档必须机器可读**。一份漂亮散文写的 PRD 没法硬门禁；结构化格式让脚本能查。AI 逐条生成 checklist（一次全出必漏，逐条不漏）
4. 验证 agent 自己会漂——**并行 subagent 独立上下文审计**，每个只看一个角度，只审不改
5. 集成验证的对象是**决策边界的兼容性**，不是文件级合并。API 契约 + 泳道 + Mock

#### 子节

- 5.1 带宽 + 盲区（开场）
- 5.2 Defense in depth：硬门禁 + 软门禁的分工
- 5.3 结构化输出：让文档机器可读
- 5.4 并行审计：subagent 独立上下文
- 5.5 集成验证：决策边界的兼容性
- 5.6 案例：一份产出从生成到通过验证

#### 素材归属

- Defense in depth 原则 + 硬软门禁 → 5.2
- 机器可读格式 + AI 逐条生成 checklist → 5.3
- Subagent 独立上下文并行审计（只审不改的前提）→ 5.4
- 前后端泳道 + Mock + API 契约 → 5.5

### 演进章 v2：harness 自己维护

**要回答的问题**：当发现—归因—修正的回路本身要工程化时，怎么做？

#### 核心 Takeaway

1. 卷一演进回路里人参与发现、归因、修正三个动作。多线程下三个动作每一个都会爆
2. **harness 必然演化，根因是 bounded attention** 不是环境在变。演化是 harness 的内在组成，不是补丁
3. **双轨制**：每次异常必须给出短期方案 + 长期方案。类比 ISO9001 异常处理流程，工程化强制
4. **变更就地打补丁 + 定期 merge 主干**。不用敏捷 epic 模式挂着；需要显式的关联结构做追溯（图数据库或 SSOT）
5. **健康度指标**：多线程下日志超出人能扫的边界，需要少量客观信号。缓存命中率是有效的 harness 健康信号；节省 token 是错的优化目标
6. **演化产物是长期资产**——harness 本身（规约、验证机制、流程模板）是可积累的东西。这条 bridge 到卷三

#### 子节

- 6.1 三个动作在多线程下都爆（开场）
- 6.2 harness 必然演化：bounded attention 是根因
- 6.3 双轨制：ISO9001 类比
- 6.4 变更机制：补丁 + merge 主干，需要显式关联
- 6.5 健康度指标：缓存命中率与信号收敛
- 6.6 演化产物作为长期资产（bridge 卷三）

#### 素材归属

- 双轨制 + ISO9001 → 6.3
- 变更就地补丁 + merge + 图数据库 SSOT → 6.4
- 缓存命中率 + 节省 token 是错的 → 6.5
- 演化产物作为资产 → 6.6

## 四、相对 5 月底稿的净改动

**Framing 校准（最关键的变化）**：
- 明确"卷一到卷二是 orchestrator 角色的转移"这一层。每章开场从这个 framing 起手
- 多 Agent / 长任务被明确降级为**触发原因**而非**主题**
- 每章的对象都从操作层升到机制层，不是"同一套 principle 在规模下重新实现"

**素材使用原则**：
- 素材是论据不是主轴（5 月底稿已有，重新强调）
- 胥的观点不需要都放进去。UE / UX 的过度强调是 PM 视角偏差，抽象成"人可判定的呈现形式"这样的普适原则即可
- 不做"harness 属于少数人 / 高手才能造 harness"这类判断。这本书是给读者学 harness 的，做精英主义判断和引言"无论你是什么程度的读者"的姿态冲突

**结构上的净变化**：
- 规约章：结构不变。takeaway 4（自包含）和 5（拆分粒度）保留分开，讲的是"每块要够厚"和"整体要够小"两个维度，5 月底稿自己 flag 的"是否合并"问题选择不合并
- 验证章：底稿 takeaway 2（defense in depth）和 3（硬软门禁）**合并成一节 5.2**。从 6 节收缩到 5 节 + 案例
- 演进章：**新增 6.4 变更机制节**（底稿没覆盖，但是很关键的读者需求）；**去掉少数人论断**；6.6 只写"harness 本身是长期资产"

## 六、写作原则

- **素材是论据不是主轴**：每段引用胥的做法时，先定位到它支撑的是哪个 takeaway，而不是反过来
- **章节对位不是硬凑**：卷一卷二对位是因为主题是意图对齐。实际写下来发现需要打破工整，可以打破
- **保持卷一的语气**：克制、不浮夸、判断鲜明。所有反直觉论断都要有充分论证，不依赖个人权威或修辞
- **每章开场明确 framing**：这件事卷一里你在做，卷二里你做不了了，harness 要接管
