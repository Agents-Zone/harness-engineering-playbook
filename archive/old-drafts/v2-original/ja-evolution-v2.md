# 進化：手動巡回から自動化ドリフト検知へ

> 🚧 本章は開発中です。以下はコア論点の概要であり、完全版は今後のバージョンで公開されます。

第1巻の進化章では spec の陳腐化の問題を議論しました。コードは変わっているのに spec が追いついておらず、Agentの成果物の品質が低下する。当時の解決策は手動巡回でした。なぜなら、あなたがまだ loop の中にいたからです。自分で監視し、specが古くなったことに気づき、自分で修正する。コストは高くなく、効果も十分でした。

第2巻はこの前提を変えました。あなたはもうリアルタイムで監視していません。複数のAgentが並列で自律的に実行し、あなたはタスク設計者・検収者であり、プロセス監視者ではありません。あなたが不在のとき、specが古くなっても誰も気づきません。Agentは古い指示に忠実に従い、一見正常だが誤った前提に基づくコードを大量に産出します。あなたが戻ってきて結果を確認したときに初めて全体がずれていることに気づきますが、その時点ですでに誤った前提に基づく大量の作業が積み上がっています。

問題の本質は、human-in-the-loop の保守モデルは human が loop を離れた後に機能しなくなるということです。解決の方向性は、システム自身にシステムを監視させることです。自動化ドリフト検知メカニズムが spec とコードの実際の状態を継続的に比較し、両者に不整合が発生した時点で能動的にアラートを出します。人が戻ってきて発見するのを待つのではなく。

これが第2巻の進化におけるコアの性質転換です。手動巡回から自動化監視へ。第1巻の進化はドキュメント保守の問題でした。あなたが気づいてあなたが修正する。第2巻の進化はシステム自己監視の問題です。あなたが不在のときにシステムがあなたの代わりに発見する。「手を離す」たびに、対応する自動化能力が追いつかなければ、手を離すことは制御を失うことと同義です。
