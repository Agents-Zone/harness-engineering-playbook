# 演进：从人工巡检到自动化漂移检测

> 🚧 本章正在开发中。以下是核心论点的概要，完整内容将在后续版本发布。

卷一的演进章讨论了规约腐烂的问题：代码在变，spec 没跟上，Agent 产出质量下降。那时的解法是人工巡检，因为你还在 loop 里。你自己盯着，发现 spec 过时了，自己去改。成本不高，效果也够用。

卷二改变了这个前提。你不再实时盯着了。多个 Agent 并行自主执行，你是任务设计者和验收者，不是过程监控者。当你不在场时，spec 过时了没有人发现。Agent 忠实地执行过时的指令，产出一堆看似正常但基于错误假设的代码。等你回来收结果时才发现全偏了，而这时候已经积累了大量基于错误前提的工作。

问题的本质是：human-in-the-loop 的维护模式在 human 离开 loop 之后就失效了。解决方向是让系统自己监控自己。自动化漂移检测机制持续比对 spec 和代码的实际状态，在两者出现不一致时主动报警，而不是等人回来发现。

这是卷二演进的核心性质转变：从人工巡检到自动化监控。卷一的演进是文档维护问题，你发现了你去改。卷二的演进是系统自监控问题，你不在场时系统替你发现。每一次"放手"都要求对应的自动化能力跟上，否则放手就是失控。
