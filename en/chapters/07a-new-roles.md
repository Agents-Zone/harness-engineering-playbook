# Redesigning Roles Around Governance

> 🚧 This section is under development.

When Agents take over the execution layer, the engineer's daily work shifts from "writing code to implement features" to "designing and maintaining the environment in which Agents execute efficiently." This environment includes the spec system, verification framework, Skill library, context engineering strategy, and feedback infrastructure. The ability to maintain this environment and the ability to write high-quality code are two different skills.

Role design needs to center on governance rather than execution. Who is responsible for spec quality. Who maintains the verification framework. Who defines the behavioral boundaries of Agents. Who ensures architectural consistency across modules. These questions were distributed across various roles during the human development era (architects handled design, QA handled testing, Tech Leads handled coordination). In the Agent era, they need to be re-aggregated and reassigned. Performance measurement needs to adjust accordingly: the metric is no longer code output volume, but the quality of the Agent execution environment and the reliability of team output.
