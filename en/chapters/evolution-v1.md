# Evolution: Keeping Specs and Verification Alive with the Code

> Pending interviews.

**Core question this chapter answers:** Code keeps changing — how do you keep specs and verification from rotting?

**Reader state entering:** Specs and verification are set up and have been running smoothly for a couple of months. Then the product starts iterating, and the system starts to decay.

**Reader state leaving:** Has mastered methods for maintaining the system in human-in-the-loop mode. Ready to move to the next stage — letting go.

**Nature of this evolution:** The developer is still in the human-in-the-loop phase — they can detect when specs go stale and fix them themselves. This is fundamentally a documentation maintenance problem: how to keep specs and code in sync at low cost.
