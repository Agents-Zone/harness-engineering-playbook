# プロセスをAgentの速度に合わせる

> 🚧 本節は開発中です。

code review、デプロイパイプライン、テストプロセス、リリース承認。これらのプロセスは人間の開発速度においては品質保証の仕組みでした。Agentの産出速度がこれらをスループットのボトルネックに変えました。しかし遅くなったからといって一律に廃止するわけにはいきません。各プロセスが当初存在していたのにはそれぞれ品質上の理由があります。

正しいアプローチは、一つずつ分析することです。どのプロセスが自動化によって加速可能か（例えばlintと型チェックで人手によるレビューの一部を代替する）、どのプロセスのトリガー頻度を調整すべきか（例えば定時デプロイからイベントベースの継続的デプロイに変更する）、どのプロセスの設計前提がすでに成立しなくなり根本的な再設計が必要か（例えばAgentが産出するPRの粒度が人間のものと全く異なる場合、レビューの単位も基準も再定義が必要になる）。目標はすべてのプロセスを速くすることではなく、品質保証のコストをAgentの産出速度に見合うようにすることです。
